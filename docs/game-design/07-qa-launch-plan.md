## 기능 QA

인수 시나리오 AC-001 ~ AC-007 이 1차 대상이며 전부 자동 또는 반자동으로 검증한다.

| 항목 | 방법 | 통과 기준 |
| --- | --- | --- |
| 판정 정확성 | domain 단위 테스트 | 게이트 4종과 반감·해소 순서의 모든 조합이 기대값과 일치 |
| 생성기 건전성 | AC-002 대량 검증 | 시드 10,000건 최종 통과율 100% |
| 결정론 | AC-003 재현 | 같은 시드·같은 선택열에서 구간별 수와 결과 100% 일치 |
| 전략 균형 | AC-004 승률 행렬 | 어떤 고정 전략도 평균 승률 60% 이하 |
| 리플레이 일치 | AC-005 | 재생 결과가 원본 기록과 100% 일치 |
| 원격 연산 상한 | AC-006 계측 | 판당 쓰기 1건, 읽기 1건 초과 없음 |
| 오프라인 완결 | AC-007 | 네트워크 차단 상태에서 판 완결, 봇 배지 표시, 재연결 시 1건 업로드 |
| 중단·복귀 | 수동 | 확약 대기 중 백그라운드 전환 후 복귀 시 남은 시간부터 재개 |
| 자동 선택 | 수동 | 제한 시간 종료 시 가장 왼쪽 칸이 선택되고 판이 멈추지 않음 |
| 저장 복구 | 손상 주입 | 손상된 저장 파일에서 직전 스냅샷으로 복구 |

## 개인정보 정책과 연령등급

- 개인정보를 수집하지 않는다. 표시명은 사용자가 정하고 실명·연락처·위치를 요구하지 않는다
- 익명 인증만 사용하며 계정 생성을 요구하지 않는다
- 만 13세 이상을 상정한다. 아동 대상 카테고리에 참여하지 않으므로 아동 정책의 추가 제약을 받지 않되,
  연령 등급 목표는 DEC-005 로 사람이 정한다
- 폭력·유혈·사행성 소재가 없다. 확률형 상품이 없으므로 확률 공개 의무 대상이 아니다
- 광고는 결과 화면 이후 보상형 1자리뿐이며 공식 정책(SRC-009)을 그대로 따른다

## 스토어와 정책

| 항목 | 내용 |
| --- | --- |
| 상표·중복 검색 | 제품명 확정(DEC-002) 전에 상표와 스토어 중복을 검색한다 |
| 스토어 문구 | 조사 대상 게임의 이름·문구·아이콘을 쓰지 않는다 |
| 데이터 안전 | 수집 항목 없음으로 신고하되 익명 식별자 사용을 정확히 표기한다 |
| 광고 표기 | 광고 포함, 인앱결제 포함으로 표기 |
| 스크린샷 | 대국 화면과 결승 충돌 장면 중심. 실제 게임 화면만 사용 |
| 타깃 API | 각 마켓의 당시 최신 요구 수준을 따른다 |

## 출시 포지셔닝과 획득

유료 획득 예산을 전제하지 않는다. 사내 실측상 출시 게임 최고 DAU 가 102 이고 유입이 제품보다
앞선 병목이므로, 획득 설계는 기능이 아니라 제품 구조의 일부로 다룬다.

- 핵심 후크 한 문장: **"같은 길을 고르면 뒤처진 쪽이 먼저 지나간다."** 규칙 하나로 설명이 끝난다(DEC-012)
- 결과 카드를 공유 가능 규격 2종으로 만든다. 카드에는 앱 이름과 최종 수만 들어간다
- 스토어 첫 스크린샷이 결승 충돌 장면이다. 2초 안에 무엇을 하는 게임인지 보여야 한다
- 초기 상대 기록 풀은 내부 플레이로 채운다. 기록이 없으면 봇 비율이 올라가고, 봇 비율이 높으면
  R-001 의 실패 경로로 들어간다

## 현지화와 고객지원

- 1차 언어는 영어와 한국어다. 규칙 설명이 텍스트에 거의 의존하지 않아 현지화 분량이 작다
- 게이트는 아이콘과 숫자로만 표시하므로 번역 대상이 아니다
- 문자열은 UI 라벨, 설정, 스토어 문구, 정책 고지에 한정된다
- 고객지원은 설정 내 문의 링크 하나로 시작한다. 상시 지원 인력을 전제하지 않는다

## 소프트론칭

- 1개 지역에서 2주간 제한 출시한다
- 관찰 지표: 온보딩 완주율, 판 완주율, 세션당 판 수, 게이트 선택 분포, 봇 대 기록 상대의 포기율 차이
- 게이트 선택 분포가 한 종류로 쏠리면 밸런스 회귀 검사를 돌려 난이도 테이블을 조정한다
- 봇 포기율이 기록 상대의 2배를 넘으면 봇 폴백 범위를 줄이고 기록 풀 확보를 우선한다

## 론칭 게이트

전부 통과해야 출시한다. 통과하지 못한 항목은 `not_run` 이 아니라 사유와 함께 남긴다.

| 게이트 | 기준 |
| --- | --- |
| G-1 인수 시나리오 | AC-001 ~ AC-007 전부 통과 |
| G-2 밸런스 | 읽기 보상 48% 이상, 선택 의미 55% 이상, 겹침 판당 0.6회 이상 (DEC-014) |
| G-3 온보딩 | 실사용자 테스트 이탈 20% 미만 |
| G-4 접근성 | 터치 대상·명암비·색 비의존·스크린리더 통과 |
| G-5 성능 | 저사양 30fps 하한, 콜드 스타트 3초 이내 |
| G-6 아트 | A-1 ~ A-5 승인 게이트 통과 |
| G-7 비용 | 판당 원격 연산 쓰기 1건·읽기 1건 계측 확인 |
| G-8 정책 | 광고·데이터 안전·연령 등급 표기 확인 |
| G-9 상대 진위 | 봇 배지가 모든 봇 대국에 표시되고 사람 표시명을 쓰지 않음 |

G-9 는 타협 대상이 아니다. 이 경계가 무너지면 콘셉트를 폐기한다(DEC-003).

## 롤백과 운영

- 규칙 값은 원격 설정으로 바꾸지 않는다. 바꾸면 과거 기록의 재생 결과가 달라진다
- 조정 가능한 값(난이도 테이블, 해금 승수, 깃털 획득량, 광고 상한, 봇 폴백 활성)만 원격으로 바꾼다
- 심각한 문제 발생 시 킬 스위치로 원격 기록 읽기를 끄고 봇 전용 모드로 내린다. 게임은 계속 동작한다
- 클라이언트 롤백이 필요하면 이전 빌드를 재배포한다. 기록 형식에 `schemaVersion` 이 있어
  구 버전 클라이언트가 신 버전 기록을 만나도 해당 버전 규칙으로 재생하거나 건너뛴다
- 월 1회 고정 전략 승률 회귀 검사를 돌리고 결과만 확인한다. 상시 운영 인력을 전제하지 않는다
