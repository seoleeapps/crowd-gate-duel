# 갈림길 군중 대전 (crowd-gate-duel)

위로 달리는 코스에서 구간마다 갈림길 게이트 셋이 내려온다. 나와 상대가 3초 안에 하나씩
비공개로 고르고 동시에 공개한다. **같은 게이트를 고르면 뒤처진 쪽이 먼저 지나간다.**

이 한 줄이 제품의 전부다. 앞서 있으면 상대가 고를 칸을 피해야 하고, 뒤처져 있으면 상대가 고를
칸을 노려야 한다. 유인이 정반대라서 매 구간 상대를 읽게 된다.

상대는 실시간 접속자가 아니라 **저장된 사람의 선택 기록**이다. 코스는 시드 결정론이고 판정은
순수 규칙이라 선택 시퀀스만 있으면 대국이 완전히 재현된다. 상시 켜져 있어야 하는 서버가 없고
판당 문서 쓰기 1건과 읽기 1건이면 사람과의 대전이 성립한다.

- 만 13세 이상, 글로벌 기본(1차 언어 영어·한국어), 세로 고정, 한 손 조작
- 판 진행 중 광고 0, 승패에 영향을 주는 유료 요소 0, 에너지 없음
- 봇은 상대 기록이 없을 때만 대체하며 화면에 봇임을 표시한다

기획 문서는 `docs/game-design/` 이 원본이며 구현은 그 계약을 따른다.

## 현재 상태

프로토타입 1~2주차 범위인 **도메인 규칙 코어와 코스 생성기·검증기**와, 4주차 범위인
**대국 조정·기록 재생·봇 폴백·로컬 저장**, 3·5주차 범위인 **대국 화면(SCR-002)·온보딩(SCR-004)·
결과(SCR-003)·홈(SCR-001)** 이 구현돼 있다. 실행하면 첫 실행은 온보딩 대국, 그 뒤로는 홈에서 시작한다.
시각 방향은 A-0 B안 "하나의 언덕길"과 A-1 1안 "한낮 장터"이며 기록은 `docs/game-design/ui/README.md` 에 있다.
꾸미기(SCR-005)·설정(SCR-006)·효과음·배경음악·햅틱도 들어 있다. 에셋의 제작 방식과 권리 근거는
`game/assets/README.md` 에 있다.

원격 기록은 아직 목 경계(`LocalRemoteRecordPort`)다. 목의 기록 풀은 **비어 있는 상태로 시작한다.**
사람이 남긴 기록이 없는데 가짜 기록에 사람 이름을 붙이면 봇을 사람으로 위장하게 되기 때문이다(DEC-003).
그래서 실제 원격이 붙기 전까지 일반 대국은 전부 봇 배지가 붙은 봇 대국이고, 기록 경로는 테스트가 검증한다.

| 인수 시나리오 | 내용 | 상태 |
| --- | --- | --- |
| AC-002 | 생성기 대량 검증 | **시드 10,000건 100% 통과** (평균 재시도 2.71회, 코스당 12.7ms) |
| AC-003 | 같은 시드·같은 선택열 재현 | 통과 |
| AC-004 | 전략 균형 | 통과 (기준은 DEC-014 로 재정의) |
| AC-005 | 상대 기록 재생 일치 | 원격 형식을 거친 기록 20건 재생이 구간별 100% 일치 |
| AC-006 | 판당 원격 읽기 1건·쓰기 1건 | 목 포트 계측으로 통과. 실제 Firestore 계측은 원격 연결 후 |
| AC-007 | 오프라인 봇 폴백·재연결 업로드 | 목 포트로 통과. 봇 배지 화면 표시는 스모크와 실행 캡처로 확인 |
| AC-001 | 온보딩 양보 사건 | 규칙 테스트와 스모크 흐름으로 통과. 실사용자 20초 이내 확인은 남음 |

헤드리스 테스트 201건과 앱 흐름 스모크(`scripts/smoke.sh`)가 전부 통과한다.

### 밸런스 실측

코스 40개 기준 전략별 평균 승률이다. 합격 판정은 아래 두 지표가 하고, 이 표는 참고 지표다.

| 전략 | 승률 |
| --- | --- |
| 경합 회피(최소 칸) | 23% |
| 무작위 | 43% |
| 항상 모으기 | 47% |
| 항상 불리기 | 57% |
| 기대값 최대 | 61% |
| 상대 추종 | 62% |
| **순위 인식** | **66%** |

- **읽기의 보상** 평균 99%, 최저 50% (기준 48% 이상) — 순위를 읽는 쪽이 탐욕 쪽을 이긴다
- **선택의 의미** 평균 74%, 최저 56% (기준 55% 이상) — 생각하고 고르는 쪽이 아무렇게나
  고르는 쪽을 이긴다

순위를 읽는 플레이가 가장 높은 승률을 낸다는 것이 이 게임의 성립 조건이다.
여기까지 오는 데 결함을 세 번 고쳤다.

| 시점 | 항상 불리기 | 기대값 최대 | 순위 인식 | 문제 |
| --- | --- | --- | --- | --- |
| 초기 설계 | 87% | 93% | — | 대칭 반감이 격차를 안 바꿔 가장 센 칸이 지배 전략(DEC-012) |
| 우선권 도입 후 | 56% | 66% | 57% | 읽기가 탐욕에 뒤짐. 동수에서 두 판단이 갈리지 않아 무승부(DEC-015) |
| 현재 | 57% | 61% | **66%** | — |

**남은 경계.** 읽기 보상의 최저값이 50% 라는 것은 일부 코스에서 읽기가 여전히 대등에 그친다는
뜻이다. 또한 이 수치는 봇 대 봇이고 상대(`기대값 최대`)가 완전히 예측 가능하다는 전제에서
나온다. 사람은 그렇게 읽히지 않으므로 **실사용자 테스트에서 다시 확인할 항목**이다.

## 구조

```text
game/                     Godot 4.7 프로젝트
  src/domain/             규칙·생성기·검증기 (Godot 노드·SDK 무의존 순수 도메인)
    rng/pcg32.gd          결정론 PRNG. 사내 matgo 구현 재사용
    rules/gate.gd         게이트 4종과 성장 계산
    rules/duel_engine.gd  구간 해소 순서와 한 판 진행
    rules/strategies.gd   밸런스 검증용 고정 전략 6종
    course/               코스 데이터·생성기·검증기
  src/application/        대국 상태 머신, 상대 기록, 봇 폴백, 기록 업로드, 진행 저장, 온보딩 코스
  src/infrastructure/     원자적 파일 저장, 원격 기록·분석·광고·공유 포트와 로컬 목
  src/presentation/       화면 전환 루트, 대국·결과·홈 화면, 색·서체 토큰
  assets/                 시안에서 옮긴 SVG 에셋, 번들 서체(OFL)
  i18n/                   영어·한국어 문자열
  tests/                  헤드리스 테스트
  tools/                  생성기 검증, 전략 행렬, 앱 흐름 스모크, 실행 화면 캡처
docs/game-design/         기획 문서 팩 (source of truth)
scripts/                  로컬·CI 공용 진입점
config/toolchain.lock     도구 버전 고정
```

`src/domain` 은 Godot 노드와 플랫폼 SDK 를 참조하지 않는다. 리플레이 재생과 대국 진행이
**같은 판정 코드**를 쓰기 때문이며, 두 경로가 갈라지면 재현이 깨진다.

## 규칙 요약

| 게이트 | 효과 | 겹쳤을 때 |
| --- | --- | --- |
| 불리기 | 내 군중 x1.3 ~ x1.8 | 뒤처진 쪽만 온전히 (동수면 절반씩) |
| 모으기 | 내 군중 + 그 구간 예상 규모의 55~135% | 뒤처진 쪽만 온전히 (동수면 절반씩) |
| 빼앗기 | 상대 군중의 15~25% 이동 | 뒤처진 쪽만 온전히 (동수면 상쇄) |
| 방패 | 빼앗기 무효화 + 상대의 10% 반격 | 양쪽 방패면 무효 |

세 성격이 순환 우위를 이룬다. 빼앗기는 성장하는 상대에게 강하고, 방패는 빼앗기에 강하며,
성장은 아무 일도 하지 않는 방패에 강하다. 여기에 **불리기와 모으기의 우열이 내 군중 수에 따라
뒤집히는** 2차 장치가 더해진다. 전환점은 `모으기 값 / (배수 - 1)` 이고, 모으기 값이 구간마다
그 시점의 예상 군중에 맞춰 커지므로 전환점이 판 내내 군중 궤적 근처에 머문다.

## 명령

```bash
# 도메인 헤드리스 테스트
scripts/test.sh

# 코스 생성기 대량 검증 (기본 10,000 시드)
scripts/validate_courses.sh --seeds 10000

# 전략 승률 행렬
scripts/strategy_matrix.sh

# 정적 검사 (컴파일 게이트와 같은 검사)
scripts/lint.sh

# 앱 흐름 스모크: 온보딩 → 결과 → 홈 → 대국 → 결과 → 꾸미기 → 설정 (사용자 저장과 분리된 경로)
scripts/smoke.sh

# 효과음 절차 생성 (결정론, 외부 음원 없음)
python3 scripts/make_sfx.py

# 실행 화면 캡처 (창을 띄워 실제 렌더러로 그린다)
godot --path game --resolution 540x1170 --script res://tools/capture_screens.gd -- --out docs/game-design/ui/runtime/1080x2340-ko
```

Godot 헤드리스는 스크립트 오류가 있어도 종료 코드 0 을 낼 수 있다. 위 진입점은 로그의
`SCRIPT ERROR` 와 `ERROR:` 를 함께 검사한다.
